============================================================
二、SUNMI T2 要怎麼開啟？
============================================================

正式建議：不要直接用檔案管理器點 index.html。

不要用這種方式：
file:///sdcard/某資料夾/index.html

原因：
1. Android 7.1.1 / WebView 對 ES Module 的 file:// 支援不穩。
2. Service Worker 不會正常運作。
3. IndexedDB / localStorage 可能異常。
4. Firebase / 線上點餐 / 印表橋接可能載入不完整。

建議在 SUNMI T2 上用 Chrome 或 WebView APK 開：

https://lcym346-byte.github.io/2237-1/

如果你之後要做本機離線版，建議不是直接點檔案，而是在 SUNMI T2 內用 APK 啟動本機 HTTP Server，例如：

http://127.0.0.1:8088/index.html

或把 POS 包成專用 Android APK / WebView APK。

三、如果打開後還是舊版畫面怎麼辦？
============================================================

這個專案有 PWA / Service Worker 快取，舊畫面可能被暫存。

請依序做：

1. 重新整理 2～3 次。
2. 或用無痕模式打開。
3. 或在網址後面加版本參數：
   https://lcym346-byte.github.io/2237-1/?v=20260517

4. 如果 SUNMI T2 還是看到舊版：
   Chrome → 設定 → 網站設定 / 儲存空間 → 找到 lcym346-byte.github.io → 清除資料

5. 再重新打開：
   https://lcym346-byte.github.io/2237-1/

四、我製作的新版主要包含什麼？
============================================================

新版包含：

1. 商用 POS 安全強化。
2. Firebase Realtime Database 安全規則檔。
3. 線上點餐安全修正。
4. 顧客查單不再讀取整個店家的所有訂單。
5. POS 端重新計算線上訂單金額，不信任客戶端送來的價格。
6. 廣告 / 促銷模板。
7. 線上點餐優惠碼功能。
8. Dashboard 發布促銷與營業時間資料。
9. 公開診斷頁不再暴露完整 POS 狀態。
10. 修復：設定 → 營業時間，設定後 F5 不會消失。
11. 共用菜單權限：所有店家讀同一份 menu/{projectId}，只有 admin 或 canPublishMenu=true 可修改主要雲端菜單。
12. 廣告立即發布到 publicOnlineStores/{storeCode}/promotions，顧客手機會自動更新，不需請客人清快取。
13. 商品上架 / 下架 / 售完會另外發布到 publicOnlineStores/{storeCode}/productAvailability；分店即使不能改共用菜單，也能同步自己店的手機線上點餐可售狀態。
14. 廣告主標題與副標題可留白；留白時顧客線上點餐橫幅不顯示該欄位。
15. 促銷模板已擴充，不只價格折扣，也包含新品上市、會員集點、贈品活動、預購預約、社群互動等活動型廣告。
16. 線上點餐顧客資訊已移到購物車內、送出訂單前填寫，減少顧客一進頁面就要填資料的阻力。
17. POS 若曾在同一裝置測試顧客線上點餐造成 Firebase 變匿名登入，系統會提示重新按 POS Google 登入；未確認的線上訂單重新載入後也會再次跳出接單提示。
18. 手機廣告讀取與 POS 發布已對齊 publicOnlineStores/{storeCode}/promotions；商品上下架/售完讀取與發布已對齊 publicOnlineStores/{storeCode}/productAvailability。

促銷類型參考：本次依餐飲/零售促銷資料整理，常見類型包含限時活動、季節/節慶、新品上市、組合/套餐、會員忠誠、贈品、預購、社群分享/推薦等；其中不是每一種都需要降價或優惠碼。

============================================================
五、哪些地方你需要手動設定？
============================================================

------------------------------------------------------------
1. GitHub Pages
------------------------------------------------------------

你需要確認 GitHub Pages 有開啟。

路徑：
GitHub repo → Settings → Pages

正式建議：
Branch: main
Folder: /root

如果要測 PR 分支：
Branch: genspark_ai_developer
Folder: /root

------------------------------------------------------------
2. Firebase 專案設定
------------------------------------------------------------

如果你要使用：
- 線上點餐
- 多店 Dashboard / 新版內建多店看板
- 雲端備份
- 即時接單

你需要在 POS 裡填 Firebase 設定：

POS → 設定 → 即時接單

新版支援兩種方式：

方式 A：手動填欄位
需要填：
- Firebase API Key
- Auth Domain
- Realtime Database URL
- Project ID
- Storage Bucket
- Messaging Sender ID
- App ID
- Measurement ID，如有

方式 B：匯入 Firebase SDK 設定檔
1. 到 Firebase Console 複製 Web SDK 設定，例如 const firebaseConfig = { ... }。
2. 存成 .txt / .json / .js，或直接貼到 POS 的「或貼上 Firebase SDK 設定內容」。
3. 在 POS → 設定 → 即時接單，按「匯入到下方欄位」。
4. 確認欄位後，再按「儲存即時接單設定」。

注意：
- Firebase Web SDK 的 apiKey 不是傳統後端密碼，但仍不建議寫死在公開 repo；新版匯入功能會存到本機 POS 設定，不會預先硬編碼到程式碼。
- 你從 Firebase Console 複製的 SDK 設定常常沒有 databaseURL。即時接單一定需要 Realtime Database URL，請到 Firebase Console → Realtime Database 頁面確認並補上。
- 不要把 service account 私鑰、Admin SDK JSON、或任何後端密鑰匯入 POS。

如果你不想讓 POS 上傳資料，請不要填 Firebase，或關閉即時接單 / 雲端功能。

------------------------------------------------------------
3. Firebase Realtime Database 安全規則
------------------------------------------------------------

我已經在 repo 內準備安全規則檔：

Firebase_Realtime_Database_安全規則.json

你需要手動到 Firebase Console 貼上：

Firebase Console → Realtime Database → Rules

貼上此檔案內容後發布。

重要：安全規則不是放在 GitHub 就會自動生效，必須手動貼到 Firebase 後發布。

------------------------------------------------------------
4. Firebase staff 權限資料
------------------------------------------------------------

新版規則需要 staff 權限模型。

你需要在 Firebase Realtime Database 建立類似資料：

staff/{你的登入 uid}/role = "admin"
staff/{你的登入 uid}/stores/store001 = true

範例：

staff
  USER_UID_HERE
    role: "admin"
    stores
      store001: true

如果沒有設定 staff 權限，你登入後可能無法讀寫部分 Firebase 資料。

------------------------------------------------------------
5. 店家代碼 / 店名
------------------------------------------------------------

目前店家設定在：

js/core/store-config.js

目前預設：

storeId: "store001"
storeName: "測試店"
storeCode: "store001"
lockFromUrl: true

如果你要正式開店，建議改成你的正式店號與店名，例如：

storeId: "main_store"
storeName: "你的店名"
storeCode: "main_store"
lockFromUrl: true

注意：
如果你改 storeId，也要同步 Firebase staff 權限：

staff/{uid}/stores/main_store = true

------------------------------------------------------------
6. SUNMI 列印橋接 APK
------------------------------------------------------------

如果你要在 SUNMI T2 列印，需要確認 SUNMI print bridge / APK 有啟動。

POS 會連：

http://127.0.0.1:8080

常用 API：
- /ping
- /print/{target}
- /drawer/open

如果你有設定 X-API-Token，POS 裡的列印橋接 token 也要一致。

如果只是測畫面，不列印，這項可以先不處理。

============================================================
六、資料會不會上傳？
============================================================

會不會上傳，取決於你的設定。

------------------------------------------------------------
情況 A：沒有設定 Firebase / Google / Apps Script
------------------------------------------------------------

資料主要存在 SUNMI T2 或瀏覽器本機：

- localStorage
- IndexedDB

通常不會上傳。

------------------------------------------------------------
情況 B：Firebase 已設定且啟用
------------------------------------------------------------

POS 可能會上傳 / 同步：

- 線上訂單
- 菜單資料
- 顧客查單摘要
- 營業時間
- 促銷資料
- Dashboard 今日營業資料
- POS 雲端備份資料

常見路徑：

onlineOrders/{storeCode}
customerOrderLookup/{storeCode}
dashboards/{storeId}
posBackup/{storeId}/state

------------------------------------------------------------
情況 C：Google Drive 備份有啟用
------------------------------------------------------------

如果你填了 Google Client ID、Folder ID 並啟用備份，資料可能備份到 Google Drive。

------------------------------------------------------------
如果你想完全離線、不上傳
------------------------------------------------------------

請確認：

1. 不填 Firebase 設定，或關閉即時接單。
2. 不使用 Google Drive 備份。
3. 不設定 Google Sheets / Apps Script。
4. 不開放線上點餐頁給客人使用。
5. 之後可再把 cloudBackup.enabled 預設改成 false，做成純離線模式。

============================================================
七、測試營業時間 F5 修復
============================================================

請照這樣測：

1. 打開 POS：
   https://lcym346-byte.github.io/2237-1/

2. 進入：
   設定 → 營業時間

3. 修改任一天，例如：
   週一 10:00 ～ 22:00
   週日取消公休或改公休

4. 按：
   儲存營業時間

5. 按 F5 重新整理。

6. 再進入：
   設定 → 營業時間

7. 確認剛才設定的資料還在。

新版也支援你修改時間後，就算沒有立刻按儲存，只要時間欄位已經觸發 input/change/blur，也會寫入本機儲存，降低 F5 遺失風險。

八、建議正式商用流程
============================================================

正式建議流程：

1. 先在 GitHub PR 合併新版。
2. GitHub Pages 指向 main 分支。
3. 用電腦瀏覽器先測 POS 主頁。
4. 用手機測 online-order.html。
5. 在 Firebase Console 貼上安全規則。
6. 建立 staff admin 權限。
7. 在 POS 設定 Firebase。
8. 在 SUNMI T2 用 Chrome 或 WebView 開 GitHub Pages 網址。
9. 測試接單、列印、錢櫃、營業時間、促銷碼。
10. 確認穩定後，再固定 SUNMI 桌面捷徑或包 APK。
